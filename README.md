# 科学计算任务运营服务

这是一个面向科研平台、实验室和计算中心的 Python 后端，使用 FastAPI 与 SQLite 管理参数模板、计算任务提交、优先级排队、工作者领取、取消、失败重试、租约恢复、用户配额、结果版本和管理员人工干预记录。服务同时保留用户、角色、会话和审计等基础能力，所有运行数据都在单个本地数据库文件中，不需要另行部署数据库、缓存、消息队列或浏览器界面。

## 已有能力

- 参数模板：保存参数类型、必填项、数值范围、默认值、最大运行时间和最大尝试次数。
- 任务提交：根据模板校验参数，使用用户与幂等键避免重复创建，并保存项目、提交人和输入摘要。
- 排队领取：按优先级和进入队列的顺序分配任务，工作者可声明算法能力并获得有期限的租约。
- 执行回执：工作者可以续租、提交结果或报告失败；可重试错误使用确定的退避时间重新排队。
- 失败恢复：租约过期后可由恢复入口将任务重新排队，达到最大尝试次数的任务转为失败。
- 配额控制：可保存用户、角色或项目的排队数、运行数和每日提交上限；当前提交路径执行用户配额。
- 结果版本：每次成功回执保存不可变结果、指标摘要和内容摘要，任务指向当前结果版本。
- 人工干预：取消、人工重试、优先级调整和批量操作均保留操作者、原因、前后状态和批次标识。
- 运营事件流：提交、领取、续租、回执、恢复和人工干预在同一事务内写入不可变事件，值班交接、内部计费等部门按订阅顺序消费，支持项目与事件类型过滤、批量领取、确认、超时重投、失败计数、死信与重新投入。
- 登录与角色：基础管理模块提供管理员初始化、用户、角色、会话和细粒度权限。

## 运行环境

- Python 3.11
- SQLite 3，由 Python 标准库提供
- Linux、macOS 或 Windows

## 安装

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
```

默认数据库位于 `./data/compute-operations.db`。可以复制 `.env.example` 并通过 `TOWNSHIP_DATABASE_PATH` 指定其他本地路径。

## 数据库初始化与检查

```bash
python -m app.cli init-db
python -m app.cli check-db
```

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8432
```

计算任务摘要位于 `/api/compute/summary`，模板、配额、提交、领取、回执和人工操作接口统一使用 `/api/compute` 前缀。

## 运营事件流与订阅

每次任务提交、领取、续租、回执（成功或失败）、租约恢复和人工干预，都会与业务变更在同一个事务里写入 `compute_events` 不可变事件流。事件键由事件类型、任务和变更后的任务版本组成（如 `task_claimed:42:3`），唯一约束保证同一业务变化只产生一个稳定事件；自增序号即全局顺序，同一任务的事件自然保持因果顺序。消费端不再需要反复扫描任务表，短暂状态也不会丢失。

订阅者（如值班交接 `duty-handover`、内部计费 `internal-billing`）通过 `/api/compute/events` 前缀的接口工作：

- `PUT /api/compute/events/subscriptions/{code}`：注册或更新订阅，可按 `project_codes` 和 `event_types` 过滤，可配置领取租约时长和最大投递次数；`start_from` 决定新订阅从开头还是最新位置开始。
- `POST .../claim`：按全局顺序批量领取匹配事件，返回带租约的投递；租约超时未确认的事件会自动重新投递，超过最大投递次数的投递转为死信。
- `POST .../ack` / `POST .../nack`：按事件编号批量确认或报告失败；确认后订阅游标 `last_ack_event_id` 向前推进，订阅者重启后从最后确认位置继续。
- `GET .../subscriptions`：管理员查看每个订阅的游标、积压数量、消费延迟、投递尝试与失败次数。
- `GET .../dead-letters` 与 `POST .../dead-letters/requeue`：查询死信原因（含失败详情），并把死信重新投入原订阅；重新投入只重置投递状态，不改写原事件。
- `GET /api/compute/events/stream`：按项目、事件类型、任务或起始序号查询原始事件流，用于审计与排障。

```text
  api/             用户、角色、认证、审计和系统管理接口

tools/             本地维护脚本
```

## 数据一致性

SQLite 连接启用外键、WAL、busy timeout 和同步写入策略。提交、领取、回执和人工干预使用即时事务；任务领取通过条件更新避免同一条排队记录被重复领取。运营事件与业务变更在同一事务提交，事件表只增不改，订阅游标单调前进，投递状态独立记录以便超时重投和死信重投。服务保存 UTC 时间字符串，测试可以注入固定时钟验证退避、租约到期、投递超时和跨日配额。会话令牌只保存摘要，审计与人工干预记录不会写入明文密码或令牌。
